# 结构与交互审查（2026-10-25）

基于 1.7.1，对插件入口、发布存储边界、配置保存、公众号渲染/排版/同步、主要弹窗、样式隔离和现有测试做了一轮审查与改进。本文记录代码判断与验证范围，不代表所有潜在缺陷已被排除。

## 已修复的问题

| 领域 | 问题 | 改进 |
| --- | --- | --- |
| 本地稿查找 | 知乎、小红书仅列举目录直属文件，移入子目录的稿件可能无法按 pub_id 找回 | Vault 发布文件递归列举，保留原文件位置；测试验证改名并移入子目录后仍找到同一稿件 |
| 排版异步请求 | 准备请求或发送前的异步读取结束后，没有重新检查窗口关闭/手工调整状态 | 检查请求版本与关闭状态；关闭前尚未发出的请求不再开始联网 |
| 排版保存 | Apply 依赖按钮禁用状态，异步回调重绘可能重新启用；读取期间关闭仍可能继续应用 | 独立保存互斥状态、固定方案快照、读后关闭检查；保存期间禁用编辑 |
| 无效预览 | 新方案超限时旧预览可能仍保留在新方案标签下 | 显示无法预览的提示；默认对比仍可查看，但超限方案不能应用 |
| 历史方案 | 只按正文 hash 筛选，历史区块映射失效时仍可能进入候选 | 用当前文档完整校验历史方案，剔除失效项 |
| 配置交互 | 多个普通设置回调直接抛出保存异常，界面缺少明确反馈 | 显示保存中/已保存/失败，捕获异常；较早保存结果不能覆盖较新的状态 |
| 外部打开 | Electron shell 不可用时可能提示“已打开” | 明确说明稿件已保存，需要外部编辑器打开 |

## 结构与重复逻辑

- `main.ts` 保留命令、插件生命周期、凭据状态和发布编排；存储实现移到 `utils/publishStore.ts`，平台选择弹窗移到 `modals/PlatformSelectModal.ts`。原有公开方法继续委托，避免一次重构改变所有调用方。
- `PublishStore` 明确 Vault / Node fs 边界，外部博客 IO 不需要实例化 Vault。覆盖备份、期望内容校验与原子写入保持原有规则。
- `utils/wechatLimits.ts` 统一正文限制和文章字段计数，覆盖本地渲染、排版预览、最终上传 URL 替换后的提交检查。字符按 Unicode 码点计数，URL 按 UTF-8 字节计数。
- `utils/wechatLayoutPreview.ts` 从弹窗中提取受控预览转换。测试可直接针对转换，不依赖 UI 模块。
- 区块角色/组件映射只定义一次；区块校验、锁定合并与编辑器查找使用 Map/Set，减少重复线性扫描。
- 风格画廊在打开窗口时创建一次，选择主题或调整组件只更新选中状态，保留 DOM 节点与键盘焦点。

## UI 调整

- 本地风格与 AI 操作分层：先选正文风格，AI 是默认收起的可选区域。
- 预览上方标明当前风格或“默认模板 · 仅供对比”，对比按钮提供 `aria-pressed`。
- 无可撤销记录时禁用撤销；没有可靠区块映射时禁用 AI 请求按钮。
- 保存时显示“正在保存排版…”，避免重复操作；错误后恢复可编辑状态。
- 提示、分组、操作区和预览容器的间距统一；窄屏通过“风格与调整 / 查看排版预览”切换工作区，底部应用/取消始终可见。
- Hexo 预览的样式选择器增加根容器作用域，避免影响其他视图。
- 编辑器控件跟随 Obsidian 主题，文章颜色继续由发布风格决定。

## 验证

- `npm test`：核心行为、故障注入、内容保真、嵌套发布目录、设置保存反馈、Unicode 长度边界。
- `npm run build`：TypeScript 检查和构建；安装文件同步到 `release/`。
- `npm run test:wechat-ui`：原有工作台回归和新增延迟请求、关闭前未发送、保存互斥、关闭后不应用、对比状态与窄屏测试。
- `npm run test:publishing-ui`：备份分页、失败重试、过期读取、关闭取消、只读原文。
- `npm run test:wechat-native`：Sandbox 原生检查 38 项；不写入 Vault、不发公众号请求。
- `npm audit --json`：本次检查未报告已知依赖漏洞。这是当前公告数据库的结果，不等于依赖绝对安全。

浏览器 UI 使用真实插件组件、浏览器 Canvas 和模拟 Obsidian API；原生检查使用运行中的 Obsidian。此次未重复真实模型或公众号写入，也没有修改远端稿件。

## 保留的设计边界

发布编排仍是入口中最大的职责。把它进一步拆为独立业务服务需要同时迁移源稿身份检查、确认锁、回滚和图片上传事务；本轮保留这些已经测试的顺序，先隔离存储和展示层，避免仅为缩短文件而隐藏跨步骤约束。

Hexo 后台与插件仍编辑同一外部发布稿，不引入双份副本、自动挂载或自动回写源稿。公众号远端不确定写入状态、冲突确认及人工恢复流程维持原有语义。跨进程外部编辑与最后一次文件替换间的极小竞争窗口等既有边界，见稳定性审查文档。
