# 贡献与文档维护约定

[文档首页](../README.md) · [开发环境](setup.md) · [架构](architecture.md) · [发布流程](releasing.md)

## 开始修改前

阅读 [AGENTS.md](../../AGENTS.md) 与 [CLAUDE.md](../../CLAUDE.md)，确认当前分支和本地未提交内容。测试中使用独立 Vault、合成稿件和临时目录，不把个人配置、真实文章或凭据提交到仓库。

每次改动应能说明具体触发条件、原行为和新行为。不要把文件拆得更多当作自动提高质量；模块边界应对应明确职责。入口当前保留发布编排，是为了让确认、上传、写入和恢复的顺序可见。

## 维护不变量

- 路径规则集中在 platforms.ts，Vault 和外部博客使用不同 IO 边界。
- 保留旧 pub_id；更新前核对归属，不能按文件名或缓存断定身份。
- 保留源附件和源正文；目标专属元数据按规则保留。
- 外部副作用必须遵守确认边界；超时后晚到响应不恢复已结束的发布。
- 微信不确定写入状态先持久化；不能把“失败就重试”用于可能已成功的新增草稿。
- 排版不得改变内容、结构和顺序；AI 不能扩大 schema 或生成任意 HTML/CSS。
- 取消、关闭、重复点击、写失败和过期返回都需要在业务层校验，不只禁用按钮。
- 所有界面 CSS 限定在插件根类名下；文章预览样式与编辑器界面样式分开。

## 扩展检查表

| 扩展 | 一起检查的文件/行为 |
| --- | --- |
| 新平台 | types.ts、platforms.ts、源/目标身份和字段规则、UI、目录检查、图片策略与文档 |
| 新排版风格 | theme 类型与预设、严格校验、画廊、AI 可选值、保真测试及实际显示 |
| 新设置 | 默认值、normalize、序列化、作用域/指纹、保存失败反馈、迁移兼容 |
| 新异步任务 | 锁在哪里、何时失效、关闭是否取消、重复调用、finally 清理与迟到结果 |
| 新远端请求 | 发送内容、目标、凭据、超时/上限、成功/拒绝/不确定结果的区分 |

## 提交与 PR

源/manifest 改动提交前运行 `npm test` 后再运行 `npm run build`，按范围补充浏览器或原生验证。提交同步的生产产物。不要提交 node_modules、临时截图、个人工具目录或 Sandbox data.json。

PR 描述先说具体问题和最终行为，再给测试证据及限制。写明是否访问真实服务、是否部署；模拟测试不能写成真实验收。若只是文档，写清核对的代码版本、图表和链接验证方法。

## 文档职责与一致性

| 内容 | 首要维护位置 |
| --- | --- |
| 产品定位与读者入口 | 项目 README、docs/README、overview |
| 用户操作 | getting-started、publishing、wechat、wechat-layout、picgo、control-room |
| 字段/默认值/命令 | reference/ |
| 实现职责和状态顺序 | development/architecture |
| 安全边界与恢复 | security、operations/ |
| 当前已实现和验证范围 | status |
| 特定时间/环境证据 | acceptance、review、releases 等记录 |

更新操作指南时核对按钮实际文本、命令注册、默认值、持久化位置和副作用。示例使用合成标题、示例域名和通用路径，不复制用户机器路径或密钥。

Mermaid 图使用简单节点和明确箭头标签，避免依赖特定渲染器的新语法；图旁提供文字解释。旧指南路径尽量保留；必须移动时同时更新入口和相对链接。历史记录保留原结论，但标注日期和覆盖范围，不把已经完成的事项继续当作当前未完成清单。

文档改动检查相对链接、锚点、代码引用与图表渲染。代码实现仍是行为核对依据；发现冲突时修正文档或明确说明待实现状态，不以文档静默改变协议。
