# 备份、恢复与迁移

[文档首页](../README.md) · [故障排查](troubleshooting.md) · [数据模型](../reference/data-model.md)

恢复前先结束发布、同步和编辑操作，记录哪些步骤已经成功。优先保留原文件和远端内容，再决定恢复哪一份；重试、清空缓存或删除稿件都不能代替状态核对。

## 需要分别备份的内容

| 内容 | 为什么需要 | 注意事项 |
| --- | --- | --- |
| 源笔记与 Vault 附件 | 原始内容与跨平台身份 | 插件不会提供完整 Vault 版本库 |
| Vault 内各平台发布稿 | 平台专用正文、封面和排版 | 公众号本地稿不是可随时重生成的缓存 |
| 外部 Hexo 仓库 | 博客稿、复制图片、主题与配置 | 不在 Vault 备份范围内时需单独备份 |
| EasyPub data.json | 账号配置、素材及草稿关联、不确定状态 | 含敏感配置，密文不保证跨机器可用 |
| 博客 `.easy-pub-backups` | 覆盖前原文 | 可能含未公开内容，不自动清理 |

访问令牌、AI 会话缓存和未加密的会话密钥不在持久化备份中。换机后应准备重新输入凭据。

## Hexo 覆盖备份

覆盖已有外部稿件前，旧全文按 SHA-256 命名为 `.bak`，放在博客根目录的 `.easy-pub-backups/`，不放到 Hexo source 下。相同内容可能复用同一备份；文件时间不是每一次发布的时间线。

设置 → Hexo → 发布历史备份：

- “检查备份”显示数量、大小和 Git 状态；不修改忽略规则。
- “查看备份”分页展示来源与只读原文，核对内容 hash；最大原文预览为 2 MiB。
- 没有来源字段就显示未知，不自动按同名稿推断归属。

恢复步骤：找到目标当前文件与对应备份 → 另存当前文件 → 核对正文、pub_id、source_file 和平台字段 → 人工恢复所需内容 → 重新检查身份、预览和构建。插件不提供自动恢复/删除按钮。

建议在博客 Git 忽略规则中排除 `.easy-pub-backups/`。已经被 Git 跟踪或推送的文件不会因增加忽略规则而消失，需另行核对仓库状态和历史。

## 本地发布中途失败

| 失败时点 | 插件行为 | 用户下一步 |
| --- | --- | --- |
| 写目标前失败 | 停止写入；按引用情况清理本次新资源 | 检查原因后重新确认差异 |
| 新目标已写，源关联失败 | 保留新目标及必要资源，不删除 | 核对两份文件的 ID/关联再重试 |
| 已有目标已写，源关联失败 | 仅当目标仍是本次写入版本时尝试恢复旧内容 | 同时查看原错误和恢复结果 |
| 目标已经被其他编辑器修改 | 不用旧稿强行覆盖新编辑 | 保留文件，人工比较合并 |
| 保存成功但打开编辑器失败 | 已保存稿件保留，提示路径 | 手工打开，不必重新生成 |
| 完成时核对失败 | 保留内容并停止自动部署 | 核对源/目标后重新发起操作 |

复制图片在目标写入后会保留，即使后续步骤失败。孤立图片宁可留待核对，也不在恢复时误删仍被引用的资源。PicGo 或微信已成功上传的远端素材不会自动删除。

## 微信不确定结果

当写请求可能已成功但响应或本地状态保存失败，插件保留 uncertain 并阻止盲目重复写入。即使报错，草稿箱也可能已经有新稿。

1. 保留本地成稿和插件 data.json，不删除 uncertain、mediaId 或整份配置。
2. 在后台检查近期草稿；在工作台使用“查询 / 恢复关联”。
3. 核对标题、正文、图片和 ID 对应关系，明确确认关联。
4. 若确定没有目标，按界面的人工恢复确认处理，再重新同步。
5. 下次同步继续核对远端冲突，不能把恢复关联理解为允许直接覆盖。

已知 ID 在写后回读失败时也会保留。内容诊断告警不应触发重新新增；先查看已保存草稿。

## 插件配置损坏

加载失败后进入保护锁定，不自动保存默认配置。先尝试“重新读取”，确认权限、文件完整性或同步软件是否仍在操作。

需要重置时，在设置页明确选择“备份后重置配置”。插件要求原文件可读、备份可回读且内容一致、原文件未改变，才写入默认配置。备份通常为插件目录下的 `data.json.recovery-<时间>.bak`，同样需要保密。

原文件不可读时，先解决读写权限或从自己的备份恢复，不要反复覆盖。重置不是文章或远端内容回滚，会清除运行关联，必须重新配置并核对微信草稿。

## 换机或改目录

分别迁移 Vault 和博客仓库；更新本机 hexoRepoPath。安装包三个文件同版，运行配置单独备份。密钥无法解密时通过向导重填；不会因为复制了密文就自动获得本机可用密钥。

修改发布根目录不自动搬稿，旧关联中的绝对博客路径也不会自动映射新电脑。移动文件前记录 pub_id，移动后用只读目录检查核对，不为同一文章重新生成所有 ID。

## 恢复能力的边界

本地操作不是跨文件事务，协作锁不是对所有编辑器有效的强制锁。插件不恢复已经群发的内容，不自动合并后台修改到源稿，也不替代系统备份或博客版本管理。排版窗口提交前取消可以阻止本地元数据修改；元数据回调已提交后关闭不撤销已经开始的写入。
