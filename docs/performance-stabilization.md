# 1.9.0 性能与交互改进记录

基线：`bdb4484b`。本轮为本地源码改进，未发布新版本或覆盖已安装插件。

## 已完成

- `PublishLocator` 缓存实际读取所得的发布稿身份。每次重新枚举目录以发现新增文件，命中的身份始终重读；Vault 修改、移动、删除及文件夹移动使对应条目失效。Hexo 每次核对设备、inode、大小、纳秒 mtime/ctime；无可靠版本信息时重新读取。解析失败、重复身份、源稿冲突及覆盖前复核仍保留。各平台索引独立且仅存于会话内。
- 智能排版控件构建一次，后续同步选择值，保持焦点、展开状态和滚动位置。预览通过 animation frame 合并刷新；关闭窗口取消待执行任务，应用时仍执行完整布局验证。
- 工作台普通预览省去语义映射的第二轮宿主渲染；打开智能排版时按需建立映射，保存的布局继续严格映射及校验。
- 仅保存文章属性时，正文、路径和布局相同且所有本地正文图片字节均通过核对，才复用已解码的正文预览。含网络正文图片或预检错误时重新处理。封面仍重新处理，同步前仍检查真实原文和图片。手动刷新、正文更新、布局变化和策略切换继续走完整渲染。
- 常驻面板对修改/重命名事件做 200ms 防抖，立即取消过期读取；展示数据相同时保留按钮 DOM 与焦点。切换稿件显示读取状态，避免沿用旧稿按钮。平台状态按点击查询，区分打开和创建。
- JPEG 跳过透明通道像素读取，其他格式继续检查透明度。封面选择器过滤 GIF/SVG 并提示先导出静态图；仍保留内容级动画检查。
- 图片明细展开后才创建行，失败明细默认展开。附件重命名只在引用路径、目录或存在未解析图片时使预览失效。
- Hexo 排版确认默认显示行号和空行标记的改动视图，完整前后内容按需创建。保留完整内容切换与保存前备份。

## 可重复验证

`npm test` 包含 `tests/performance.test.ts`：

| 夹具 | 断言结果 |
| --- | --- |
| 100 / 1,000 / 5,000 份发布稿 | 首次分别读取 N 份；重复查询单一身份只重读 1 份 |
| 20 / 100 / 300 个正文区块 | 普通预览 1 次宿主调用；严格映射 2 次 |
| 0 / 5 / 20 张 JPEG | 普通预览 1 次宿主调用；不调用全像素透明度扫描 |
| PNG 透明像素 | 保持 PNG 编码，不误转 JPEG |
| 本地图片原始字节变化 / 网络图片 | 拒绝复用旧正文预览 |
| 连续修改组件与锁定 | 控件对象不变，最新组件不被旧闭包覆盖；一帧内合并刷新 |
| 300 区块超出 HTML 限制 | 保留禁止应用的保护 |
| 重复身份 / 无效 YAML / 扫描期间失效 | 保留拒绝或冲突结果 |
| 连续正文保存 | 侧栏按钮及焦点保持 |
| Hexo 改动/完整模式 | 默认不创建完整双栏，切换时创建且可再次隐藏 |

2026-10-28 本机运行样例：5,000 份内存稿件首次约 13 ms、重复查询约 1 ms。该夹具使用内存读取和 JSDOM/模拟 Canvas，只用于算法、调用次数与资源生命周期回归，不代表磁盘、真实 Obsidian、图像编解码耗时或内存峰值。测试每次打印定位时间；不以容易受机器负载影响的毫秒阈值作为通过条件。

本轮 `npm test` 与 `npm run build` 通过，生产 bundle 同步到 `release/`。应用内浏览器使用仓库已有 `tests/preview-workbench.mjs` 和合成稿件确认：智能排版按需打开、调整后锁定保留组件、仅改作者后正文图片 URL 复用、图片列表展开前后行数为 0 / 1；平台查询后显示创建入口；320px 工作台无水平溢出且控制台无错误。

本机未运行会启动外部 Chrome/Chromium 的完整 Playwright 套件；该限制来自当前工作区浏览器执行规则。原生 Obsidian 大 Vault 的磁盘耗时、主线程长任务、内存峰值，以及真实公众号视觉验收仍需在独立测试 Vault / CI 中补充。不能把上述夹具或浏览器抽查写成完整压力测试已完成。
