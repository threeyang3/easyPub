# 1.9.0 性能与交互改进记录

基线：`bdb4484b`。本轮为本地源码改进，未发布新版本或覆盖已安装插件。

## 已完成

- `PublishLocator` 缓存实际读取所得的发布稿身份。每次重新枚举目录以发现新增文件，命中的身份始终重读；Vault 修改、移动、删除及文件夹移动使对应条目失效。Hexo 每次核对设备、inode、大小、纳秒 mtime/ctime；无可靠版本信息时重新读取。解析失败、重复身份、源稿冲突及覆盖前复核仍保留。各平台索引独立且仅存于会话内。
- 智能排版控件构建一次，后续同步选择值，保持焦点、展开状态和滚动位置。预览通过 animation frame 合并刷新；关闭窗口取消待执行任务，应用时仍执行完整布局验证。
- 工作台普通预览省去语义映射的第二轮宿主渲染；打开智能排版时按需建立映射，保存的布局继续严格映射及校验。
- 仅保存文章属性时，正文、路径和布局相同且所有本地正文图片字节均通过核对，才复用已解码的正文预览。含网络正文图片或预检错误时重新处理。封面仍重新处理，同步前仍检查真实原文和图片。手动刷新、正文更新、布局变化和策略切换继续走完整渲染。
- 常驻面板对修改/重命名事件做 200ms 防抖，立即取消过期读取；展示数据相同时保留按钮 DOM 与焦点。切换稿件显示读取状态，避免沿用旧稿按钮。平台状态按点击查询，区分打开和创建。
- JPEG 跳过透明通道像素读取，其他格式继续检查透明度。封面选择器过滤 GIF/SVG 并提示先导出静态图；仍保留内容级动画检查。
- 图片明细展开后才创建行，失败明细默认展开。附件重命名只在引用路径、目录或存在未解析图片时使预览失效。
- Hexo 排版确认默认显示行号和空行标记的改动视图，完整前后内容按需创建。保留完整内容切换与保存前备份。

## PR #8 复审修复与原生实测（2026-10-28）

- 保留动画帧预览验证期间禁用应用的设计。浏览器断言等待校验完成后才检查可用性，此时旧 AI 请求仍未返回；同时修正超限用例按严格映射后的 HTML 计算边界，编辑器测试夹具显式建立映射。
- 排版窗口用请求集合跟踪传输寿命，当前版本单独决定是否可更新方案；失效的旧请求不阻止发起下一次明确确认的 AI 请求。每个窗口最多两个未结束请求，达到上限仍允许已验证的手工方案应用。旧请求的 finally 只清理自己的条目，不会解除新请求的等待状态；反向返回和手工覆盖均有回归测试。不会自动重发请求或取消服务端计费。
- 平台按钮在检查、打开或创建失败后回到“检查稿件”，保留错误提示，下一次点击重新查询，避免局部状态永久过期。

通过 `node tests/run-wechat-native.mjs --performance` 在 macOS Obsidian 的 Sandbox 执行。使用原生 MarkdownRenderer、真实 JPEG 编解码、临时 Vault 附件和真实本地磁盘文件；测试后删除本轮生成的数据。原始记录见 [performance-native.json](verification/performance-native.json)。

原生预览覆盖 20/100/300 区块与 0/5/20 张图的完整组合，每组各执行普通和严格映射模式。300 区块、20 张图的普通/严格预览为 129.3 / 161.9 ms；100 区块、5 张图的已保存布局为 43.4 ms。300 区块的测试内容超过 HTML 字符限制，仍正确报告超限，没有截断。完整逐项值在 JSON 中，单次测量受首次加载、系统缓存和其他插件影响，不作为稳定的速度排名。

本次测量期间，Sandbox 渲染进程 V8 堆起始约 56.3 MiB、结束约 67.4 MiB，观测最高约 77.1 MiB；16ms 定时器最大额外延迟约 13.8 ms，Long Task observer 未记录 ≥50ms 的任务。采样包含其他插件和测试文件准备，不强制 GC，观测最高值不等于精确内存峰值，也不能据此认定长期无泄漏或所有文章均无卡顿。
