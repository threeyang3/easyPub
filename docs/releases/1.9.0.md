# EasyPub 1.9.0

常驻发布面板统一发布入口；Hexo 增加一键排版，生成发布稿时可以直接导入图片；公众号工作台为文章设置和封面编辑提供更大空间。

## 新增与改进

- 常驻发布面板可从工具栏或命令打开，支持跟随活动文章、固定文章、查看关联发布稿，以及直接进入 Hexo 管理、预览与排版。
- Hexo 一键排版仅修改发布稿：普通段落的逐行文本转换为空行分段，清理段末空格和文末空行；显式硬换行（两个尾随空格或反斜杠）也转换为段落分隔。结构化 Markdown 区域受保护，保存前展示差异并备份，再次核对源稿和目标内容。
- 生成发布稿、初始化原稿和刷新属性时可导入图片并选择封面。图片先保存到 Obsidian 配置的附件目录，自动避让同名文件；取消后已经保存的附件保留。Hexo 在确认生成时再复制到博客的 `source/picture/easy-pub/{pub_id}`，或按启用的 PicGo 设置上传。
- 公众号工作台默认在主区域打开，正文预览、文章信息、图片与封面分别使用完整内容区；宽窗口可并排预览。账号入口随连接状态更新。
- 独立编辑横版与方形封面裁剪，支持选新封面后直接裁剪、最后一次性保存。外部正文或图片变化时阻止旧裁剪应用；拖动复用已解码图片并合并画布重绘。
- 补齐浏览器测试依赖隔离、保存前源稿快照核对，以及异步读取和过期状态保护。

## 兼容性与升级

最低 Obsidian 版本从 1.4.4 提高到 **1.5.7**，因为附件导入依赖宿主的附件路径 API；仍仅支持桌面端。历史版本 **1.8.0 → Obsidian 1.4.4** 的兼容性记录保留，新版本单独记录为 **1.9.0 → 1.5.7**。

备份并保留已有 `data.json`，使用本 Release 同一次构建的 `main.js`、`manifest.json`、`styles.css` 一起替换，结束忙碌任务后重载。升级不会批量迁移原稿或自动创建远端草稿。

## 验证范围

核心测试、TypeScript 检查、生产构建，以及 GitHub Actions 的 macOS、Windows、Linux 构建和两套浏览器回归构成合并门禁。macOS Obsidian Sandbox 已完成工作台 20 项原生检查和系统文件选择器 4 项检查，见[工作台验收](../verification/workbench-stability-native.json)与[文件选择器验收](../verification/attachment-picker-native.json)。

本轮未重新执行真实微信或 AI 服务端到端测试；最低宿主版本、Windows/Linux 原生交互仍需独立验收。发布状态、最终提交及附件以 GitHub Release 为准。
