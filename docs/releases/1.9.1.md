# EasyPub 1.9.1

性能与交互稳定性更新。针对大目录、长文章和连续编辑减少重复读取、图片处理与界面重建，并修复 AI 排版请求失效后的操作状态。

## 改进与修复

- 发布稿身份使用会话索引和文件版本核验，减少重复正文读取，保留身份冲突、无效 Front Matter 和覆盖前复核。
- 普通公众号预览延迟建立语义映射，打开智能排版或使用已保存布局时继续严格验证。仅保存属性时，核对本地图片字节后复用正文预览；网络正文图片仍重新处理。
- 排版控件保持焦点与展开状态，按动画帧合并预览校验。旧 AI 请求不会覆盖手工方案或阻塞下一次明确确认的请求；每个窗口最多两个未结束请求。请求开始/结束只更新按钮，不重绘已验证的正文，保留文本选择与滚动位置。
- 发布面板对保存事件防抖，展示数据不变时保留控件；平台稿件按需查询，操作失败后可重新检查。
- 图片明细展开后创建，JPEG 跳过透明度像素扫描；封面选择器过滤 GIF/SVG 并提示导出静态图片。
- Hexo 排版默认显示带行号及空行标记的改动，全文按需展开。改动视图正确处理 Windows CRLF 换行，实际文件继续保留原换行风格。

## 兼容性与升级

最低 Obsidian **1.5.7**，仅支持桌面端，与 1.9.0 相同。无批量数据迁移，不改变公众号远端写入协议。

升级前结束发布任务并备份配置，使用本 Release 的 `main.js`、`manifest.json`、`styles.css` 一起替换，保留已有 `data.json` 后重载插件。旧版 1.9.0 的标签与安装附件保持不变。

## 验证与限制

运行核心测试、TypeScript 检查、生产构建、三系统 CI 及微信/发布管理两套浏览器回归。功能改动已在 PR #8 合并前通过完整 CI；版本提交同样执行发布门禁，最终结果以关联 CI 和 Release 为准。

macOS Obsidian Sandbox 原生样例覆盖 100/1,000/5,000 份真实磁盘合成稿件与 20/100/300 区块 × 0/5/20 张图。5,000 份稿件首次建立索引约 498ms、热查询约 78ms，热查询仍进行 5,001 次 stat。完整记录和测量边界见[性能记录](../performance-stabilization.md)与[原始数据](../verification/performance-native.json)。

首次索引不代表清空系统磁盘缓存；本地合成文件结果不能推广到网络盘或云同步目录。未重新执行真实微信/AI 服务的端到端验收，最低宿主版本、Windows/Linux 原生交互和长期内存稳定性仍需独立验证。正式发布状态、最终提交及附件以 GitHub Release 为准。
