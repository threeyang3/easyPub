# 稳定性审查记录（2026-10-14）

本轮覆盖发布事务、差异确认、源与目标变更、图片缓存、设置恢复、Front Matter 解析、Hexo 子进程和 Control Room 探测。

## 修复

- PicGo / Control Room 请求缺少等待上限：增加超时，超时后释放操作状态，迟到结果不再写入稿件。
- 设置损坏导致加载失败：验证字段并回退安全默认值，不在加载阶段覆盖原文件。
- 差异窗口打开异常可能残留确认锁：异常时清除锁，后续发布可以继续。
- 确认期间源文本、路径或设置变化：上传与写入前复核；缓存图片也验证内容哈希。
- 相同内容但不同路径的图片共用上传占位符：占位符同时包含路径与内容身份。
- 发布后编辑器打开失败误报整个发布失败：单独提示已保存的目标路径。
- 在发布稿中再次发布到自身可能破坏元数据：写入前识别同一文件并提示返回源文章。
- 默认解析器支持可执行 JavaScript Front Matter：明确拒绝，只接受数据格式。
- 序列化会再次解析正文开头：改为直接写入正文，保留开头的分隔线或示例，避免二次解析执行。
- Hexo 部署类型用正则检查会接受空值或注释：解析 YAML 并验证每项部署类型，构建前检查配置。
- Obsidian 的模块解析器不支持原来的目录定位方式：使用博客目录下的 Node `createRequire`。
- 当前 Obsidian 忽略 Electron Node 模式开关：在 Electron 中使用 PATH 上的系统 Node.js，缺失时明确报错。
- 后台发现过程中的并发部署：先持有部署锁，并在所有退出路径释放。

## 验证

- `npm test`：原有核心测试及新增故障注入回归通过。
- `npm run build`：TypeScript 检查和生产打包通过，根目录与 `release/` 三个文件一致。
- Obsidian 1.14.4 / Electron 43.7.7 的 Sandbox 临时插件：加载、源元数据更新、图片复制、代码示例保留、真实差异窗口确认、目标并发修改保护通过。
- 同一宿主中运行临时 Hexo 命令入口：系统 Node.js 正确执行 `clean`、`generate --bail`；验证的是子进程调用链，不是完整博客主题构建。
- 测试稿件与临时插件已清理，Sandbox 原受限模式已恢复。

## 结论与边界

正常配置下，已验证的发布主链路可用；本轮修复了会导致任务悬挂、误报失败和宿主命令无法执行的问题。附件缺失、冲突、无效 YAML 等情况仍应停止该次操作，修复后重试，避免以损坏数据换取表面成功。

未执行真实图床上传、公开网站部署，未覆盖所有 Obsidian 版本、主题和文件系统。网络超时仅结束插件等待，不能保证第三方图床取消上传。仍需对实际博客及图床进行发布前验证，不能把自动化通过等同于所有环境下无故障。
