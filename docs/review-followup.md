## PicGo 凭据保护（2026-10-22）

后续解耦：平台默认模式不加载 PicGo 凭据、不运行连接检查、不调用上传处理器，PicGo 专用设置不参与发布指纹。公众号也忽略 PicGo 开关。保留配置与缓存供重新选用；确认后切换处理模式仍需重新预览，避免把旧上传占位符写入稿件。测试用无效地址、不可解密密钥和抛错上传处理器验证默认发布正常完成。

- 旧明文 Secret 自动迁移到系统加密存储；加密不可用时仅保留会话值。所有设置保存剥离明文，按调用顺序写入快照，避免连续修改时旧写入覆盖新值。
- 无法解密时保留密文并阻止新的上传，设置提供重新填写和清除入口。上传错误过滤当前密钥及 Bearer 值，不直接传播认证回显。
- 保持原有图床地址、附件哈希缓存及 Markdown 格式。测试覆盖迁移、加密不可用、解密失败、清除、保存顺序及失败恢复、错误脱敏；加密实现复用已有 Electron safeStorage 封装，真实系统密钥链和 PicGo 上传仍需宿主验收。

## 本轮：源文章身份关联

- 生成或打开已有稿件前，以 `pub_id` 查找全部候选，核对发布稿的 `source_file` 和 Vault 中其他源稿的 ID。
- 明确属于其他源稿、多个源稿占用同 ID、同一平台存在多个同 ID 发布稿时停止，不自动覆盖、重置 ID 或修复关系。
- 提交前再次检查关联，覆盖非 Hexo 平台，避免确认期间关联发生变化。
- 副本需要独立发布时，仅在确认其为副本后移除该副本的 `pub_id` 和 `子文件` 字段再发布；原文章不变。移动或重命名应先核对原关系，不盲目生成新 ID。

## 向后兼容约束

- 不引入必须迁移的元数据字段，不限制历史 ID 的长度或格式。
- 保持普通路径、wiki 链接、带 `.md` 后缀和别名的 `source_file` 可用。
- 缺少 `source_file` 或链接因重命名失效的旧稿，未发现其他源稿占用同 ID 时仍沿用已有关系。
- 检查过程不写入文章、旧配置或缓存；保留正文及平台专有字段。无关笔记的错误 YAML 不阻止当前文章发布。
- 归属无法从现存信息中确定的情形仍有局限：例如原文章已删除、仅留下缺失来源字段的旧发布稿。没有新增不可恢复的身份迁移，后续可增加明确的人工关联流程。

## 第二批：目标写入保护

- Vault 内已有稿件使用 `vault.process`，在同一个原子读改写回调中核对确认内容；发现期间编辑时停止，不覆盖新内容。该 API 自 Obsidian 1.1.0 提供，最低宿主版本保持 1.4.4。
- Hexo 写入使用目标旁的 `.<文件名>.easy-pub.lock` 排他锁，遇到正在写入的实例立即停止，不等待或自动抢锁。异常退出遗留锁时，报错显示完整路径；确认所有发布任务停止后才可手动移除。
- 覆盖已有 Hexo 稿件前，把原文保存到博客根目录 `.easy-pub-backups/<原文 SHA-256>.bak`，落盘成功后才继续。相同内容复用备份并核对内容；备份失败或损坏时停止发布。备份在 `source` 外，不作为博客文章参与生成。
- 锁内重新核对目标内容，首次创建继续采用排他创建，覆盖及恢复旧内容均经过相同写入保护。
- 恢复时先停止发布，打开 `.bak` 核对正文和元数据，另存副本后再决定是否替换原稿。备份包含文章全文，不自动清理，也不是自动回滚日志；请按需要保管并把 `.easy-pub-backups/` 加入博客仓库的本地忽略规则。
- 不自动修改博客配置、Git 忽略规则、历史文档或 ID。插件数据和发布文档的存储格式不变。

验证包含并发发布只能成功一次、残留锁拒绝写入、备份内容、备份失败保留目标、失败后释放锁与重试，以及 Vault 修改前内容已经变化的场景。

提交前复核补充：锁清理失败单独记录警告，不把已成功写入报告为写入失败，也不覆盖原始写入错误；遗留锁仍阻止下一次发布。故障注入测试验证实际目标内容、警告与下次发布阻断。

## 第三批：失败回滚不误删

- 目标写入成功但源文章关联更新失败时，新建稿件保留，不再执行“读取后删除”，避免删除期间发生的用户编辑。错误中给出目标路径和关联核对提示。
- 已有稿件仅在当前内容仍等于本次写入内容时恢复旧版，沿用 Vault 原子内容检查和 Hexo 发布锁；稿件变化、消失或恢复失败时停止，保留原始失败原因和恢复错误，不强制覆盖。
- 目标写入成功后的失败分支保留本次新增附件，避免回滚清理造成仍被使用的附件丢失。可能留下可人工清理的孤立附件，以数据保留优先。
- 不更改正文、ID 格式或历史元数据字段。新增稿件保留后再次发布仍经过现有 ID 与源文章归属检查，不自动重新关联。

回归验证：源关联写入失败后恢复旧稿；恢复前被用户修改时保留编辑并同时报告两个错误；新稿失败后不删除用户修改；相关附件保留。

## 第四批：备份路径复核与代码示例保护

- 修正备份目录误用 Hexo URL 根路径的问题：目录从配置中的本地博客仓库路径计算，不依赖 `_config.yml` 的 URL 或 root。回归测试实际读取仓库内备份，避免只检查发布结果而漏掉备份位置。
- 通用图片嵌入处理改用已有 Markdown 解析器提供的语法位置，跳过围栏代码、缩进代码、跨行行内代码、HTML 和已有 Markdown 图片内部；转义的 wiki 图片引用保持原样。
- 不重新序列化文章，仅替换正文中需要处理的 wiki 图片引用，保留 LF/CRLF、空白、图片顺序和旧有附件解析规则。未引入新依赖，未更改图床配置和上传 API。
- 回归覆盖带文字的伪结束围栏、较短或不同类型的围栏、未闭合代码块、引用和列表中的代码块、缩进代码、跨行行内代码、转义引用，以及代码块后的正常正文图片。
