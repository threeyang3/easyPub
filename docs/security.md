# 安全与隐私边界

[文档首页](README.md) · [配置参考](reference/configuration.md) · [恢复指南](operations/backup-and-recovery.md)

以下描述当前实现的处理边界，不是对外部服务、其他 Obsidian 插件或所有网络环境的安全保证。

## 数据会发送到哪里

| 动作 | 目标 | 发送内容 |
| --- | --- | --- |
| 默认本地稿生成/本地风格排版 | 本机文件与宿主 | 不调用 AI 或平台发帖接口 |
| Hexo 图片复制 | 配置的本机博客目录 | 附件副本和平台稿 |
| PicGo 上传 | 用户配置的 PicGo Server | 本地附件绝对路径、可选 Server Secret；由 PicGo 上传到图床 |
| 公众号预览网络图 | 图片 URL | 网络下载请求；不等于微信上传 |
| 公众号同步 | 微信接口 | 图片字节、封面、文章 HTML 与字段，以及所需认证 |
| AI 排版 | 用户配置的兼容接口 | 确认展示的标题、区块片段和排版指令；可选 API Key |
| 管理后台/Hexo 预览 | 经验证的本机服务 | 临时会话认证和文章 pubId 等请求 |

## 凭据

AppSecret、AI Key 和 PicGo Server Secret 在系统加密可用时加密；不可用时支持会话内保存。加密依赖本机系统环境，不应把可解密性视作跨设备承诺。不可解密的原密文通常保留，用户通过对应入口替换或清除。

微信 access_token 仅缓存在内存。日志和 UI 不应暴露网络错误中的认证 URL、请求头或密钥。插件配置、恢复备份与后台会话文件都不应公开提交；系统加密不能代替文件权限或安全的备份管理。

## AI 输入与输出

AI 只在展示完整目标和载荷、用户明确发送后调用。代码与图片内容使用占位，覆盖嵌套代码和行内代码；URL 从规划片段中去除。正文中的普通可见私人信息仍可能进入片段，用户应在发送前检查。

请求消息上限 64 KB、等待 45 秒、输出 max_tokens 4096；响应在解析前限制 256 KB。宿主 requestUrl 先缓冲响应，因此该限制不是网络接收阶段的流式上限。超时或关闭不会保证服务端停止处理或计费。

模型输出是不可执行数据：严格校验 schema、hash、区块 ID、组件和角色，拒绝未知字段和 locked。AI 不生成可执行 HTML/CSS，不改变正文、链接和图片顺序。缓存只在会话内保存有限方案和摘要键，不保存请求正文或原始密钥。

## Markdown、HTML 与图片

Front Matter 接受数据型 YAML/JSON，不执行 JavaScript。公众号 HTML 经白名单清理再套本地样式；不支持的嵌入和复杂内容会提示转换。远端对比内容以可读文本呈现，备份原文也是只读文本。

仅 Vault 附件模式在宿主渲染前拒绝原始 HTML，并在各图片处理阶段重查策略。允许网络图时，下载有总超时、接收字节、重定向和 URL 检查；拒绝明显私网/特殊地址与 HTTPS 降级。但域名解析到内网和 DNS 重绑定不在完整覆盖范围内。该策略也不是其他 Markdown 插件的网络沙箱。

素材缓存按账号和用途隔离，复用前复核必要状态；正文和封面有不同尺寸/格式限制。图片处理不会删除源附件。具体限制见[公众号指南](wechat.md)。

## 本地服务与外部执行

Control Room 发现要求绝对目录、固定脚本和精确 GUI 命令；复用会话要求回环 URL、唯一合法 token 和状态探测。文章 iframe 只接受验证后的固定回环预览地址；不会把任意后台返回 URL 嵌入页面。

Hexo 使用仓库已有本地依赖；启动命令不读取 shell 启动脚本、不将博客仓库加入 PATH。运行博客自己的 Hexo 或管理后台仍意味着执行该仓库代码，应仅对自己信任的仓库配置该能力。

## 写入、取消与恢复

确认、快照、身份检查、原子写入和备份减少误覆盖，但不能提供跨文件或跨设备事务。设置读失败锁定普通写入；微信结果不确定时阻止重复创建并要求恢复关联。

排版窗口的取消检查执行到宿主元数据回调前，提交后的写入不能靠关闭窗口回滚。已发出的图片/AI/微信请求可能继续完成；处理恢复时应核对实际状态，不直接删缓存重试。

## 报告问题

使用合成内容和脱敏日志说明触发条件，避免在公开 issue 附原配置、真实凭据或完整私人稿件。依赖审计只反映当时已知公告，不能证明代码或依赖绝对安全。验证范围和剩余事项见[当前状态](status.md)。
