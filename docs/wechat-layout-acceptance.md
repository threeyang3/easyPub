## 真实账号发现与修复

- 研究主题、活动主题、重点卡片样式均在草稿接口回读中保留；标题、段落、嵌套列表、引用、表格、代码和链接可见文字保持原顺序，原 Markdown 正文哈希不变。
- 当前测试账号会移除 GitHub 外部链接的 `<a>`，但保留文字。插件新增同步后诊断，明确提示实际链接改写，不能将 API 写入成功当作链接可点击的保证。
- 微信把正文图片的 `src` 改成 `data-src`，将 HTTP 原图 `/0` 转为 HTTPS `/640` 规格。回读诊断按受控微信 CDN 的素材标识比较，只忽略已知规格和 `from`/`wx_fmt` 参数；不同素材、未知参数、数量或顺序仍会提示差异。
- 未进行群发或正式发布。测试草稿保留为“EasyPub智能排版验收-可删除”。原始本机证据不包含在公开仓库中。
- 用户自行配置 AI 后，真实调用经过请求片段审查、严格方案校验和预览内容比较，随后应用并更新同一草稿。返回方案包括导语、列表重点卡片、引用、总结，客户端保留另一张手工锁定卡片；原 Markdown 哈希不变。微信回读保留总结组件样式，素材条目数量不变，实际外链改写仍有明确提示。
- 新增读取期间正文变化的竞态检查；校验必须在异步读取前后确认工作台版本。过时 AI 请求不会阻止用户应用新手工方案，也不会覆盖新方案；重复的待刷新计时会被手动刷新取消。
- 用户最初反馈“暂时只能确认后台，手机稍后检查”，随后于2026-10-25确认“手机预览也正常，继续吧”，完成选定风格的手机验收。

## 配套博客检查

独立博客副本的 `npm run test:gui` 通过，包括新增数字、长十六进制、中文及带点历史短链接测试，以及认证、路径穿越与加密文章排除保护。`npm run check` 的隐私、内容、链接、监听器和主题检查通过，完整构建因副本没有加密文章所需的密码而停止。未读取、复制或伪造真实密码，不能声明本机完整博客构建通过。

另外使用隔离的最小 Hexo 站点实际生成五种历史短链接页面，验证输出路径与原 `abbrlink` 保留，不接触生产文章或密码。该检查已接入配套后台的预览回归。CI 初次仅 macOS/Node 24 的既有文件监听测试超时，重跑相同提交后六组构建全部通过；没有放宽或修改监听测试。

## 代码块视觉反馈与修复

用户提供的朱砂风格截图显示，两行测试代码在微信展示时合并为一行。真实接口回读仍保留原始换行和 `white-space:pre-wrap`，因此此前的接口保真检查不能证明视觉换行正确。改为每行受控空白样式和显式 `<br>`，保留原始换行文本；清理、映射及重复处理均保持原代码文字和缩进。回读与冲突文本比较能识别显式换行，避免把编辑器删除冗余原始换行误报为代码丢失，同时仍报告实际丢行。

核心测试覆盖空行、缩进、制表符、HTML 字面值与重复清理；浏览器测试模拟删除原始换行空白后，核对两行仍位于不同纵向位置。核心、构建、浏览器和36项原生回归通过。Sandbox 已安装修复，现有朱砂测试稿已更新，接口回读确认显式换行及逐行空白保护样式保留。用户随后确认后台和手机预览正常，完成选定朱砂风格的视觉验收。
